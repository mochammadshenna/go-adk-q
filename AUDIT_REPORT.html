The application is fundamentally sound — it already implements a buffered multi-provider failover chain, a rich Bubbletea TUI (8 themes, model picker, file attach, ACP server, session save), and a clean Genkit boundary. The risk was not in what exists, but in what was invisible and duplicated: a second, unwired fallback implementation, a /model switch that silently destroyed redundancy, and the absence of a per-attempt timeout that could hang the whole request.

Spark. The single highest-leverage change was not a new feature — it was making resilience visible. The failover chain now reports which provider served each turn, surfaced live in the TUI footer (⚡ groq / 🔀 fell back to groq) and via /providers. Reliability you can see is reliability you can trust.

2 · Methodology

Read-first, trace-everything. We did not guess; we exercised the code.

① Read the surface

Full read of cmd/tui/chat.go (2,721 lines), main.go, the two fallback files, oaibridge, echo, session.go, slash.go.

② Trace the flow

Mapped the exact request path: TUI → chatModel.startAgentStream → ADK runner.Run → failover.Model.GenerateContent → per-provider oaibridge → Genkit.

③ Prove it

Ran the pipeline with ECHO_FALLBACK_ENABLED=1 and observed a real 400 from HuggingFace, recovery via echo, and the new route stats. go build ./... + go test ./model/... ./cmd/... green.

Reference UI studied: huggingface/tau (Textual-based coding agent — events-as-contract, durable sessions, provider catalog, context accounting).

4 · Provider Fallback — Deep Investigation

This was the user's explicit priority. We traced it end-to-end and found the mechanism is correct but under-instrumented and partially defeated by surrounding code.

4.1 What actually runs

The live chain is failover.New(primary, backups...) (model/failover/failover.go). It iterates providers left→right, calls each with stream=false, buffers the full response, and returns the first success. It skips nil entries and drops (nil,nil) heartbeat sentinels. On total failure it yields errors.Join of every provider error. This is sound.

4.2 The hidden second implementation

model/middleware/fallback.go is a Genkit ai.Middleware that re-implements fallback with richer semantics (status-code-aware retry, IsolateConfig). A repo-wide grep confirms it is referenced nowhere outside its own test. It is dead code that (a) confuses maintainers about "which fallback is real" and (b) risks a future engineer "fixing" fallback in the wrong file.

4.3 Three ways the safety net was leaking

① Defeated by /model

Old switchModelCmd built a single provider — no failover. Switching models dropped every backup. HIGH

② No per-attempt timeout

A provider that accepts the connection but never replies blocks the request forever; ctrl+c can't interrupt a ctx-ignoring SDK. HIGH

③ Error-only retry

A 200 with an {"error":...} body, an empty response, or a content-filter refusal is treated as success. No response validation. MED

4.4 Divergence between binaries

Root main.go built its chain without OpenCode; cmd/tui/main.go included it. Two copies of the same inline constructor had silently drifted — different provider sets, different priority. Classic duplicated-logic rot.

4.5 Streaming trade-off (by design, but real)

Because failover buffers the full response and oaibridge ignores the stream flag, the TUI's "streaming" actually dumps the complete message at once after the provider finishes. This is a deliberate reliability-over-latency choice — but it means time-to-first-token is gated by the slowest primary before any fallback can even be considered.

Net assessment. The fallback core is well-built. The defects were in adjacent code that undermined it (switch path, missing timeout) and in duplication/observability that hid it. All four are now addressed.

6 · TUI Enhancements Delivered

Inspired by tau's emphasis on visible state (sessions, provider catalog, context accounting), we made the TUI's resilience tangible rather than cosmetic.

⚡ Live failover route badge

Footer now shows ⚡ groq (primary served) or 🔀 fell back to groq after every turn — the headline "wow" that proves the safety net is alive.

/providers panel

Lists the full priority chain (▶ marks the active primary) and the exact outcome of the last response, including which providers failed before recovery.

Fallback survives /model

Switching models now keeps every other configured provider as a backup. Redundancy is never silently dropped.

Per-attempt timeout

A 90s deadline per provider means a dead upstream can no longer hang your session — it fails over cleanly.

The existing TUI was already delightful (themes, model picker, @file autocomplete, ACP server, session save). We extended it, we did not rebuild it — the mark of a maintainable codebase.

7 · Verification (real, not asserted)

End-to-end run with ECHO_FALLBACK_ENABLED=1 and a stray HF_TOKEN in the environment — the primary provider genuinely failed and the chain recovered:

This is the mechanism working as designed — and now the TUI can show it to the user in real time.
